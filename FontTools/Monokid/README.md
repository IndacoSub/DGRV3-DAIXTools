# FONTTOOLS - MONOKID
## Team DAIX, 2026  

---

Monokid is the **fourth stage** of the FontTools pipeline and the final step before UPS patch generation (Monosuke).  
Its job is simple to describe but absolutely critical to the integrity of the entire FontTools workflow:

> **Monokid ensures that ONLY modified SPC font archives are included in the final distribution.  
> Nothing more, nothing less.**

This prevents accidental redistribution of untouched copyrighted assets and guarantees that the output of FontTools is clean, minimal, and safe to publish.

---

## ⚠️ IMPORTANT WARNING  
Monokid **deletes files**.  
Not casually. Not metaphorically.  
It *literally deletes SPC archives* that were not modified during compilation.

If you run Monokid in the wrong folder, you will lose data.

Monokid assumes:

- You are inside a **clean DGRV3-Font repository** cloned by Monotaro  
- Monophanie has already extracted and duplicated base fonts  
- Monodam has already compiled fonts and produced `list_changed.txt`  
- You understand that FontTools is **not** a casual modding tool

If any of these conditions are false, **stop**.

---

## 🎯 PURPOSE

Monokid performs the **distribution filtering** stage of FontTools:

- Cleans empty files from `base_fonts` and `base_fonts_copy`
- Reads `list_changed.txt` (generated by Monodam)
- Identifies which SPC archives were actually modified
- Deletes all SPCs that were *not* modified
- Copies the remaining SPCs into `ModifiedFiles-Font/`

This ensures that the final output contains **only modified SPCs**, ready for UPS patch generation or DailyManager distribution.

DGRV3-Font/

## 🔧 INTERNAL WORKFLOW (step-by-step)

### 1. Locate required folders
Monokid resolves:

- `DGRV3-Font/base_spc`
- `base_fonts`
- `base_fonts_copy`
- `ModifiedFiles-Font` (created fresh)

If `base_spc` is missing, Monokid aborts immediately.

---

### 2. Clean empty files  
HTFont and SpcTool occasionally leave behind empty files.  
These must be removed before filtering.

Monokid deletes:

- Empty files inside `base_fonts`
- Empty files inside `base_fonts_copy`

This prevents false positives during SPC matching.

---

### 3. Read `list_changed.txt`  
Monodam writes one entry per modified SPC:

base_spc/base_fonts/.../fontname.spc


Monokid:

- Normalizes paths (`\` → `|`, `/` → `|`)
- Removes file extensions
- Builds a list of modified SPC identifiers

If `list_changed.txt` is missing, Monokid cannot determine what changed.

---

### 4. Filter SPC archives  
For each SPC inside `base_fonts`:

- Normalize its path
- Strip extension
- Compare against `list_changed`
- If NOT found → **delete the SPC**
- If found → keep it

This is the core of Monokid.

---

### 5. Copy modified SPCs  
Finally, Monokid copies the filtered `base_fonts` directory into:

ModifiedFiles-Font/


This folder becomes the **final output** of FontTools before UPS patch generation.

---

## 📦 OUTPUTS

After running Monokid, you will have:

ModifiedFiles-Font/
(only modified SPC archives)


This folder is consumed by:

- **Monosuke** (UPS patch generator)
- **DailyManager** (for Daily SPC uploads)
- Any external automation pipeline

## 🧩 ROLE IN THE FONTTOOLS PIPELINE

Monokid is stage **4** of the canonical FontTools sequence:

1. **Monotaro** — clone/update DGRV3-Font  
2. **Monophanie** — extract tools, prepare fonts  
3. **Monodam** — compile fonts, insert STX/SRDV into SPC  
4. **Monokid** — filter modified SPCs  
5. **Monosuke** — generate UPS patches (optional)

Monokid is the “cleaner” and “gatekeeper” of the pipeline.

---

## 🛠️ TROUBLESHOOTING

### “Distribution folder already exists”
Monokid deletes it automatically.  
This is normal.

### “File does not exist!”
This means Monodam referenced an SPC that wasn’t found.  
Check your repository layout.

### “ModifiedFiles-Font is empty”
This means Monodam did not modify any SPCs.  
Check `list_changed.txt`.

---

## 🧠 DESIGN PHILOSOPHY

Monokid is intentionally strict:

- No heuristics  
- No guessing  
- No partial matches  
- No fallback behavior  

If an SPC is not explicitly listed in `list_changed.txt`, it is deleted.

This guarantees:

- Minimal output  
- No accidental redistribution  
- Perfect reproducibility  
- Clean DailyManager uploads
